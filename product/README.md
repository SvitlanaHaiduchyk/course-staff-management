# Списки заборонених слів (denylist)

Тут лише списки для `npm run spec:check` — перевірки анонімізації: жодне слово з них не має трапитися в `requirements/`,
`openspec/`, `docs/`, `src/`, `supabase/`, `tests/`, `README.md` і `AGENTS.md` (збіг за початком слова, без урахування
регістру, тож ловляться й відмінки).

- `product/denylist.local.txt` — **локальний**, у `.gitignore`: справжні назви клієнта (список PM надсилає особистим
  повідомленням). Git його не відстежує, `npm run spec:check` читає його й значень не друкує. Агентам не відкривати
  (у Claude Code — deny у `.claude/settings.json`, у Cursor — `.cursorignore`).
- `product/denylist.txt` — публічний і необов'язковий: слова, які можна показувати, але не можна писати в репо (наприклад,
  назви внутрішніх систем). Створіть, якщо потрібно; рядок із `#` на початку — коментар.
- У CI ті самі справжні назви — секрет репозиторію `SPEC_DENYLIST` (через кому).

Вимог PM тут немає: їхній знімок — `requirements/` (приносить команда `/requirements-sync`).
