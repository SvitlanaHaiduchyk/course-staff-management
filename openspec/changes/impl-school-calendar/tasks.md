# Задачі зрізу school-calendar

Кожна задача — вертикальний зріз і окремий PR «Реалізація» з гілкою `task/<коротко>`. Галочки ставимо в PR задачі; archive зміни — в останньому PR зрізу.

Порядок не випадковий: задача 1 дає чисті функції, якими далі користуються і сторінка заявки, і тести; задача 2 — таблицю, без якої немає нічого; задачі 3–5 — екрани; задача 6 — вплив на баланс, найтонше місце.

## 1. Обрізання розкладу — чисті функції

Правило «закрито» без бази: що лишається від блоків дня після закриття і яке повідомлення показати. Першим і окремо, щоб `AC-CAL-04` і `AC-CAL-05` мали тести ще до будь-якої міграції.

- [ ] `src/lib/leave/closure.ts` — тип `Closure` (назва, `startsOn`, `endsOn`, `closesAt`), `closureOn(closures, date)`, `closedFrom(closure)`
- [ ] там само — `blocksAfterClosure(blocks, closedFrom)`: блок у процесі обрізається, наступні відпадають
- [ ] `src/lib/leave/validate.ts` — закрита на цілий день дата не приймається, текст `schoolClosedMessage(name)`
- [ ] `tests/leave-closure.test.ts` — числа з прикладів PM: 08:30–15:30 із закриттям 12:00 → 08:30–12:00 (210 хв); 13:00–17:00 із закриттям 12:00 → жодного блоку

Done when: AC-CAL-03, AC-CAL-04, AC-CAL-05

## 2. Схема: таблиця закриттів, RLS і функція додавання

Міграція з таблицею `school_closures`, обмеженням перетину дат, політиками на кожну операцію й функцією `public.add_school_closure`, яка робить перевірку й запис однією транзакцією.

- [ ] Міграція `*_school_calendar.sql`: `btree_gist`, таблиця, `check` на назву, дати й крок 5 хвилин, `exclude using gist` на перетин
- [ ] RLS: `revoke all … from anon, authenticated`; `select` — усім авторизованим; `insert`, `delete` — лише `private.current_app_role() = 'admin'`; політики `update` немає й `grant update` не видаємо
- [ ] `private.closure_on(date)`, `private.closed_from(date)` — `security definer`, `set search_path = ''`
- [ ] `public.add_school_closure(...)` — `security invoker`, дослівні тексти `AC-CAL-07`, `AC-CAL-10`, `AC-CAL-11`; для скороченого дня блокують лише записи з хвилинами після часу закриття
- [ ] `tests/db/school-calendar.test.ts` — відмовні AC на рівні бази

Done when: AC-CAL-07, AC-CAL-08, AC-CAL-10, AC-CAL-11, AC-CAL-13

`/calendar` для кожного авторизованого: закриття одного навчального року в порядку дат, перемикач років, порожній стан.

- [ ] `src/app/calendar/page.tsx` — список, навчальний рік за замовчуванням — поточний
- [ ] порожній стан: «No closed days in school year 2026–2027»
- [ ] пункт «Шкільний календар» у шапці — бачить кожен авторизований
- [ ] `tests/e2e/calendar.spec.ts` — неавторизований бачить сторінку входу й жодної назви закриття

Done when: AC-CAL-01, AC-CAL-02, AC-CAL-14, AC-CAL-15

## 4. Адмінський екран: додати й прибрати

`/calendar/manage` — форма додавання й кнопка прибирання, обидві лише для адміністратора.

- [ ] `src/app/calendar/manage/page.tsx` — перевірка ролі в самій сторінці, текст «Only an administrator can change the school calendar»
- [ ] server action `addClosure` — виклик `supabase.rpc("add_school_closure", …)`, помилки `Alert` варіанта `destructive`
- [ ] server action `removeClosure` — `delete` за `id`
- [ ] `supabase/demo-closures.json` і `npm run closures:demo` — тестові закриття
- [ ] тести: відмова не-адміністраторові, успішне додавання й прибирання

Done when: AC-CAL-09, AC-CAL-12

## 5. Вплив на заявку

Сторінка заявки бере закриття й працює з обрізаним розкладом: закрита дата відпадає зі своїм повідомленням, решта дат лишається.

- [ ] `src/app/requests/` — читання закриттів тижня, «цілий день» за обрізаним розкладом
- [ ] закрита дата у заявці на кілька дат відпадає, інші створюються (як `AC-LEAVE-21`)
- [ ] перевірка: `AC-LEAVE-07` у день без закриття показує **повний** розклад — текст той самий, перелік інший
- [ ] тести на межу: закриття рівно на кінці останнього блоку закриває 0 хвилин

Done when: AC-CAL-03, AC-CAL-04, AC-CAL-05 (разом із задачею 1 — тут наскрізний шлях)

## 6. Вплив на баланс

Знаменник частки дня втрачає закриті хвилини. Найтонше місце зрізу: міняється функція, від якої залежать уже прийняті `AC-BALANCE-02`, `-03`, `-05`, `-06`.

- [ ] Нова міграція `*_closed_minutes.sql`: `create or replace` для `private.working_minutes_on` — віднімає закриті хвилини
- [ ] `private.decide_leave_record` — новий знаменник, сигнатура й логіка поділу ті самі
- [ ] `tests/db/` — приклад PM: цілий день 08:30–12:00 при закритті з 12:00 списує **1.00**, а не 0.50
- [ ] регрес: `AC-BALANCE-02`, `-03`, `-05`, `-06` у дні **без** закриття дають ті самі числа, що й раніше
- [ ] **умовна, лише якщо PM відповість B на Q10**: перерахунок `days_on_type` і `days_unpaid` уже погоджених записів при додаванні й прибиранні закриття

Done when: AC-CAL-06
