# Задачі зрізу school-calendar

Кожна задача — вертикальний зріз і окремий PR «Реалізація» з гілкою `task/<коротко>`. Галочки ставимо в PR задачі; archive зміни — в останньому PR зрізу.

Порядок не випадковий: задача 1 дає чисті функції, якими далі користуються і сторінка заявки, і тести; задача 2 — таблицю, без якої немає нічого; задачі 3–5 — екрани; задача 6 — вплив на баланс, найтонше місце.

**Доповнено 2026-11-18** за відповідями PM (`…spec#22` … `#26`) і зміною специфікації `align-school-calendar`: зріз виріс із 15 AC до 20. Нові AC не стали окремими задачами — кожен ліг у ту задачу, де вже живе його механізм: `AC-CAL-16` у задачі 1 і 5, `AC-CAL-17` … `AC-CAL-19` у задачу 2, `AC-CAL-20` у задачу 6. Умовна задача на перерахунок часток зникла: відповідь PM збіглася з варіантом, який ми й планували.

## 1. Обрізання розкладу — чисті функції

Правило «закрито» без бази: що лишається від блоків дня після закриття і яке повідомлення показати. Першим і окремо, щоб `AC-CAL-04` і `AC-CAL-05` мали тести ще до будь-якої міграції.

- [x] `src/lib/leave/closure.ts` — тип `Closure` (назва, `startsOn`, `endsOn`, `closesAt`), `closureOn(closures, date)`, `closedFrom(closure)`
- [x] там само — `blocksAfterClosure(blocks, closedFrom)`: блок у процесі обрізається, наступні відпадають
- [x] `src/lib/leave/validate.ts` — закрита на цілий день дата не приймається, текст `schoolClosedMessage(name)`
- [x] `tests/leave-closure.test.ts` — числа з прикладів PM: 08:30–15:30 із закриттям 12:00 → 08:30–12:00 (210 хв); 13:00–17:00 із закриттям 12:00 → жодного блоку
- [x] `src/lib/leave/validate.ts` — перевірка закриття **перед** перевіркою порожнього розкладу: коли обрізання не лишило блоків, перемагає «The school is closed on this day: …», а не «You have no working hours on this day» (`AC-CAL-16`)
- [x] тест на межу `AC-CAL-16`: лишився хоч один блок до часу закриття → дата **приймається** з обрізаним розкладом, повідомлення немає

Done when: AC-CAL-03, AC-CAL-04, AC-CAL-05, AC-CAL-16

**Стан:** задачу закрито. Код переніс `git cherry-pick d6fdd2b` зі застарілої локальної гілки `task/closure-functions` на гілку від свіжого `main` (мердж знищив би чужу роботу: та гілка відстала на весь дизайн і два знімки вимог). ## 2. Схема: таблиця закриттів, RLS і функція додавання

Міграція з таблицею `school_closures`, обмеженням перетину дат, політиками на кожну операцію й функцією `public.add_school_closure`, яка робить перевірку й запис однією транзакцією.

- [x] Міграція `*_school_calendar.sql`: `btree_gist`, таблиця, `check` на назву, дати й крок 5 хвилин, `exclude using gist` на перетин
- [x] RLS: `revoke all … from anon, authenticated`; `select` — усім авторизованим; `insert`, `delete` — лише `private.current_app_role() = 'admin'`; політики `update` немає й `grant update` не видаємо
- [x] `private.closure_on(date)`, `private.closed_from(date)` — `security definer`, `set search_path = ''`
- [x] `public.add_school_closure(...)` — `security invoker`, дослівні тексти `AC-CAL-07`, `AC-CAL-10`, `AC-CAL-11`; для скороченого дня блокують лише записи з хвилинами після часу закриття
- [x] там само — перевірки назви **до** вставки з дослівними текстами: порожня → `AC-CAL-18`, довша за 100 символів → `AC-CAL-19`; плюс «Enter the start and end dates» і «Enter the closing time» (припущення PM без AC)
- [x] там само — перетин із **кількома** закриттями: зібрати всі, по одному разу, з першою спільною датою кожного, впорядкувати за датою, з'єднати через «, » (`AC-CAL-17`)
- [x] `tests/db/school-calendar.test.ts` — відмовні AC на рівні бази
- [x] тест, що саме **функція**, а не `check`/`exclude`, дає ці тексти: помилка Postgres із назвою обмеження тест має валити

Done when: AC-CAL-07, AC-CAL-08, AC-CAL-10, AC-CAL-11, AC-CAL-13, AC-CAL-17, AC-CAL-18, AC-CAL-19

**Зроблено.** Міграція `20261118094510_school_calendar.sql`. ## 5. Вплив на заявку

Сторінка заявки бере закриття й працює з обрізаним розкладом: закрита дата відпадає зі своїм повідомленням, решта дат лишається.

- [ ] `src/app/requests/` — читання закриттів тижня, «цілий день» за обрізаним розкладом
- [ ] закрита дата у заявці на кілька дат відпадає, інші створюються (як `AC-LEAVE-21`)
- [ ] перевірка: `AC-LEAVE-07` у день без закриття показує **повний** розклад — текст той самий, перелік інший
- [ ] тести на межу: закриття рівно на кінці останнього блоку закриває 0 хвилин
- [ ] наскрізний шлях `AC-CAL-16`: дата, де скорочений день забрав увесь розклад, відпадає з назвою закриття

Done when: AC-CAL-03, AC-CAL-04, AC-CAL-05, AC-CAL-16 (разом із задачею 1 — тут наскрізний шлях)
