# Знімок вимог PM

Цю теку заповнює **лише** команда агента `/requirements-sync` (Claude Code і Cursor) з репо вимог PM
(`https://github.com/<pm>/<team-slug>-spec`). Після першої синхронізації тут будуть файли PM, а цей файл зникне:

- `product.md` — продукт: бачення, ролі й матриця прав, глосарій, roadmap зрізів, що поза межами (issue «Продукт» або
  `docs/product.md` у репо PM);
- `<N>-<slug>.md` — вимога PM (issue «Вимога» `#N` або файл `docs/requirements/…`): Навіщо · Користувачі й ролі ·
  Основний сценарій · Критерії приймання (`AC-<AREA>-<NN>: Дано … Коли … Тоді …`) · Поза межами · Припущення ·
  Відкриті питання · Журнал змін.

Перший рядок кожного файлу — `> Джерело: …`: issue PM і час його оновлення або файл і коміт PM. Далі — текст PM дослівно.

- Руками тут нічого не змінюйте: кожен `/requirements-sync` замінює теку цілком, а PR «Оновлення вимог» містить лише її
  і шапку `docs/conformance.md`. Що й коли змінював PM — `git log -p -- requirements`.
- Вимоги PM — ще не ваша специфікація: ви перекладаєте їх в OpenSpec (`openspec/`, зміна `add-<зріз>`, PR
  «Специфікація»), зберігаючи ID критеріїв PM. `npm run ac:coverage` попереджає про AC PM, яких ще немає в
  `openspec/specs/`.
- Незрозуміле у вимогах — issue «Питання до вимог» у репо PM через вебформу (скіл `spec-clarify`), а не правка тут.
- Звідки й коли знімок — рядок «Вимоги: …» у шапці `docs/conformance.md`.
